# bybit-lab — числовой слой для Bybit

Рыночные данные Bybit → точные числа для модели, PNG-график для человека.

## Зачем

График — это картинка для глаз. Модели нужны числа: они точные, воспроизводимые
и дешёвые по токенам. Поэтому здесь два независимых выхода:

| Выход | Для кого | Команда |
|---|---|---|
| таблица / JSON | машина | `--json` |
| PNG-график | человек (контроль) | `--png file.png` |

Индикаторы считает **TA-Lib** (не LLM), поэтому результат детерминирован:
один и тот же вход всегда даёт один и тот же выход.

## Данные

Публичный REST Bybit V5 (`/v5/market/kline`, `/v5/market/tickers`).
**API-ключ не нужен**, авторизации нет, только чтение.

## Установка

```powershell
uv venv --python 3.13
uv pip install -r requirements.txt
```

## Запуск

```powershell
# для человека: сводка + график
.\.venv\Scripts\python.exe bybit_lab.py --symbol BTCUSDT --interval 60 --png chart.png

# для машины: только JSON
.\.venv\Scripts\python.exe bybit_lab.py --symbol BTCUSDT --interval 60 --json

# другой рынок / таймфрейм
.\.venv\Scripts\python.exe bybit_lab.py --symbol ETHUSDT --category spot --interval 15
```

Параметры: `--symbol`, `--category` (spot/linear/inverse), `--interval`
(1/3/5/15/30/60/120/240/360/720/D/W/M), `--limit` (до 1000), `--json`, `--png`.

## Что считается

- **Тренд**: EMA 20/50/200, отклонение цены от каждой, состояние стека (bull/bear/mixed)
- **Моментум**: RSI(14), MACD(12,26,9) + гистограмма и её предыдущее значение
- **Волатильность**: ATR(14) в цене и в %, ширина Bollinger (20,2) и `%b`
- **Структура**: позиция в 100-барном диапазоне, доля тела и теней свечи, объём к SMA(20)
- **Контекст**: 100-барные high/low и расстояние до них в %
- **24ч**: изменение, high/low, открытый интерес (из tickers)

## Связь с MCP

В OpenCode подключён официальный `bybit` MCP (396 инструментов), но через
`permissions` разрешены **только 28 рыночных**. Торговля, плечи, переводы,
конвертации, боты и стратегии заблокированы на уровне конфига — независимо от
наличия API-ключа.

MCP удобен агенту для разовых запросов; этот скрипт — для воспроизводимого
пайплайна и запуска без OpenCode.

## `microstructure.py` — датчик микроструктуры + честный scorecard

Отдельный эксперимент: **может ли LLM читать рынок лучше монетки**.

Разделение труда жёсткое и намеренное:

| Кто | Что делает |
|---|---|
| `microstructure.py collect` | **датчик**. Собирает стакан, имбаланс, фандинг, OI, L/S, taker-flow, ATR → компактная таблица. Прогнозов **не делает**. |
| Агент (LLM) | **аналитик**. Читает таблицу + сырые стаканы топ-10 и пишет вызовы **с обоснованием**. |
| `microstructure.py evaluate` | **судья**. Сверяет замороженные вызовы с фактом. |

```powershell
# 1. собрать микроструктуру (агент прогнозов не делает)
.\.venv\Scripts\python.exe microstructure.py collect --top 200 --raw-top 10

# 2. агент читает micro\table_*.txt и пишет micro\agent_calls_*.json  <-- руками/агент

# 3. сверка
.\.venv\Scripts\python.exe microstructure.py evaluate micro\collect_*.json micro\agent_calls_*.json
```

Оценка идёт **по минутным свечам постфактум**, а не по запуску планировщика ровно
в срок: цены на +15 и +60 минут восстанавливаются из истории, поэтому сон или
опоздание задачи не портят измерение.

Документ на выходе разделяет два принципиально разных числа:

- **бета** — где вызов совпал с тупым правилом «моментум продолжается»;
- **анализ** — где вызов от дрейфа **отклонился**.

Только второе подмножество проверяет навык. Обоснования пишутся в файл **до**
факта, поэтому подогнать их задним числом невозможно.

> Исследовательский инструмент, не инвестиционный совет. `hourly_forecast.py`
> (первая, слабая версия эксперимента) оставлен для истории и не используется.

## `microstructure_v2.py` — исправленный датчик + кривая «точность против горизонта»

Первая версия датчика была **плохо откалибрована**, поэтому её нулевой результат
не тестировал микроструктуру: измеряли не то. v2 чинит четыре дефекта и добавляет
главное — оценку на **каждой минутной дистанции 1…60**.

Что было сломано в v1 (проверено на реальном сборе 200 символов):

| Дефект | v1 | v2 |
|---|---|---|
| Стакан обрезался до ±0.01–0.47% | 9 из 10 сырых стаканов усечены | `limit=500`, покрытие в bps пишется в колонку `cov`, вместо вранья — `na` |
| Полосы без проверки покрытия | `imb5 == imb25` у 78/200 | `imb5 == imb25` у 0/200 |
| Окно потока у каждого своё | 31 с у BTC против 367 с у 1000PEPE | одно общее 120-секундное окно на все символы |
| Метрика глубины на 50 bps | BTC/ETH туда не достают → фейковое `-100%` | 5 bps (`DEPTH_CHANGE_BPS`) |

Порядок сборки принципиален: **сначала окно потока, потом снимок структуры, и
T0 = запрос тикеров ПОСЛЕ снимка.** Тогда любое чтение структуры — это история
относительно T0, заглядывания вперёд нет. Цена этого — устаревание (`snap_span_s`).

```powershell
# 1. датчик
.\.venv\Scripts\python.exe microstructure_v2.py collect --top 200 --flow-top 40 --book-top 5 --risk-top 50 --window 120 --out-dir micro2

# 2. агент пишет TSV; конвертер валидирует набор символов и штампует время фиксации
.\.venv\Scripts\python.exe freeze_calls.py micro2\collect_*.json micro2\agent_calls_*.tsv

# 3. судья: горизонты 1…60 минут от момента ФИКСАЦИИ вызовов
.\.venv\Scripts\python.exe microstructure_v2.py evaluate micro2\collect_*.json micro2\agent_calls_*.json --horizon-max 60
```

Горизонты считаются **от момента фиксации вызовов**, а не от снимка. Если бы
точкой отсчёта был снимок, то каждая минута между снимком и фиксацией утекала бы
в короткие горизонты уже случившимся движением и льстила агенту. Базовая цена и
цена горизонта берутся из одного и того же минутного ряда — инструмент сравнения
не подменяется.

В отчёте есть колонка **«Я строго»**: попаданием считается только ход, который
превысил спред на момент снимка; отскок в пределах спреда не засчитывается.

> Многогоризонтность — это много сравнений на одной выборке. Даже при полном
> отсутствии сигнала максимум из 60 точек систематически выше среднего, поэтому
> «лучший горизонт» сам по себе ничего не доказывает. Отчёт печатает шум ±SE и
> колонку «Всегда вниз» — с ней и надо сравниваться.
